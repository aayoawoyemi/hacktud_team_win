    design / rationale

    The first question is “which nodes are connected?” The first screen answers it. Model controls, joining and logs stay available without competing with that view.

    • Task-first hierarchy. Remove competing information; disclose secondary details when needed. NN/g ↗
    • Aligned, compact data. Keep numeric columns aligned and give selected rows a separate detail view. Carbon ↗
    • Useful terminal conventions. Concise feedback and discoverable help. Keyboard commands supplement buttons. This web layout is not a literal CLI. CLI Guidelines ↗
    • One color model. All explicit colors use OKLCH. Color-space choice does not automatically ensure contrast. MDN ↗

    Project constraints: no marketing headline, decorative chart, glass, glow, scanlines, typewriter effects, copied LUMA identity or invented live performance. These are choices for this tool, not a universal formula for avoiding generic design.

    Selected by Joseph: layout C (Multiplexer), Graphite, SF Mono and model controls in the inspector. Connected nodes remain the opening view. Selecting a node returns to its details. This clean preview has no design-choice controls. Live integration is still pending.
