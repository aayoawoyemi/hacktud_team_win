# CONTRACTS.md

The shared agreements between teammates and their agents. Anything another person's code depends on lives here.
Change this file first, ship it on its own, then build against it. `git sync` prints this file's diff whenever it changes.

- Source of truth for every message and service: `crates/contracts/proto/contracts.proto` (package `contracts.v1`).
  This file describes it in prose; if the two disagree, the `.proto` wins and this file gets fixed.
- Background and the reasons behind each shape: PRD §6 on the `notes` branch (`git show origin/notes:PRD.md`).
- Changing a contract: add fields, never rename, renumber or delete them. Post `concept-change` in issue #11.

## Data types

All types are generated by `crates/contracts/build.rs` (tonic + prost, compiled with `protox`, so no `protoc`).
Use them as `contracts::Heartbeat`, `contracts::SplitPlan`, and so on. Every type has serde derives, so
`serde_json::to_string(&msg)` writes the JSON form below.

### JSON form (PRD §6.0)

- snake_case field names, exactly the `.proto` field names.
- Every top-level message has `schema_version` (currently `1`, constant `contracts::SCHEMA_VERSION`).
- Sizes are integer bytes; fields mirroring llama.cpp output keep MiB and say so (`free_mib`).
- Times are RFC 3339 UTC strings. Durations are integers with a unit suffix (`_ms`, `_s`).
- `null` means unknown or not measured. Missing fields read as their default; unknown fields are ignored.
- Enums are strings: lower-case for kinds and states the PRD writes in lower case (`"running"`, `"node_lost"`,
  `"llama_default"`, `"helper"`), upper-case for the §5.6 states (`"SERVING"`, `"ACTIVE"`), and the §6.11
  spelling for error codes (`"E_PORT_IN_USE"`). An unknown string reads as the enum's `Unspecified` value.
- These lists are `null` when empty: `StartRpcServerArgs.devices`, `SplitPlan.tensor_split`,
  `LaunchSpec.tensor_split`, `LaunchSpec.devices`, `DevicePlacement.actual_layers`, `LlamaServerStatus.metrics`,
  `LlamaServerStatus.slots`.
- Layer ranges (`layers`, `planned_layers`, `actual_layers`) are two-element arrays `[first, last]`, inclusive.

### Command and CommandResult (the one shape that differs from PRD §6.3)

`Command.kind` and `args` work as §6.3 shows. `CommandResult` adds a `kind` field that echoes the command kind,
so a reader knows which shape `data` has. It is absent when the command failed without data.

| `kind` | `args` (Rust type) | `data` on success (Rust type) |
|---|---|---|
| `start_rpc_server` | `StartRpcServerArgs` (every field optional; null = rpc-server default) | `StartRpcServerResult { pid, banner: RpcServerBanner }` |
| `stop_rpc_server` | `StopRpcServerArgs` (`{}`) | `StopRpcServerResult { exit_code }` |
| `probe` | `ProbeArgs` (`{}`) | `NodeCapabilities` |
| `speed_probe` | `SpeedProbeArgs { method }` (method is O-22) | `SpeedInfo` |
| `netcheck` | `NetcheckArgs { target_addr, duration_s }` | `NetcheckResult` |

In Rust: `Command.args: Option<command::Args>` and `CommandResult.data: Option<command_result::Data>`.

### Shapes PROPOSED here, owned by the consuming work package

§6 shows these only as `null`; the contract gives each a shape so it can be typed. The owning WP may add fields.

- `LlamaServerStatus.metrics`: map of Prometheus metric name to value, from llama-server `/metrics` (WP-7).
- `LlamaServerStatus.slots`: list of `SlotStatus { id, n_ctx, is_processing }`, from `/slots` (WP-7).
- `BenchResult.server_timings`: `ServerTimings`, the fields of llama-server's `timings` object (WP-8).
- `Event.data`: string-to-string map; numbers go in as text (WP-4, WP-9).
- `LaunchSpec.speculative`: `SpeculativeSpec`, one field per flag in the §6.6 table (WP-S1).

### llama.cpp output parsers (`contracts::parsers`)

Every parser skips `load_backend:` and `ggml_vulkan:` lines and accepts `\n` or `\r\n`.

| Function | Input | Output |
|---|---|---|
| `parse_list_devices(&str)` | `llama-server --list-devices` | `Vec<DeviceInfo>` (fills `unified_memory` from `ggml_vulkan: ... uma: N` lines when present) |
| `parse_version(&str)` | `--version` | `LlamaVersion { build, commit, built_with }` |
| `parse_rpc_server_banner(&str)` | rpc-server start output | `ParsedRpcBanner { banner: RpcServerBanner, devices: Vec<DeviceInfo> }` |
| `parse_device_line`, `vulkan_uma_flags`, `is_noise_line` | single lines | building blocks |

## API routes

Control-plane transport is gRPC (O-03). Plaintext (no TLS) on the local network.

| Service (served by) | Method | Request | Response | Caller |
|---|---|---|---|---|
| `AgentService` (every node agent) | `Execute` (unary) | `Command` | `CommandResult` | coordinator |
| `CoordinatorService` (coordinator on main) | `Register` (unary) | `RegisterRequest { capabilities, agent_addr }` | `RegisterResponse { accepted, error, coordinator_version }` | agent, at start and whenever its capabilities change |
| `CoordinatorService` | `StreamHeartbeats` (client stream) | stream of `Heartbeat` | `HeartbeatStreamSummary { received }` when the stream ends | agent, one stream kept open |

- `agent_addr` is the `host:port` where that agent's `AgentService` listens. Port numbers are O-17 (open).
- If the coordinator doesn't know a node that streams heartbeats (for example after a coordinator restart), it
  ends the stream with gRPC status `FAILED_PRECONDITION`, and the agent registers again.
- Rust: `contracts::v1::agent_service_server::{AgentService, AgentServiceServer}`,
  `contracts::v1::agent_service_client::AgentServiceClient`, and the same names with `coordinator_service`.
  `crates/contracts/tests/grpc_loopback.rs` shows both services running over TCP.
- Known llama.cpp ports (not ours): rpc-server 50052, llama-server 8080.
