# CONTRACTS.md

The shared agreements between teammates and their agents. Anything another person's code depends on lives here.
Change this file first, ship it on its own, then build against it. `git sync` prints this file's diff whenever it changes.

- Control plane (D-13): a SpacetimeDB module, `crates/control/src/lib.rs`. Its tables and reducers are the API
  (section "Control plane" below). Source of truth for the §6 payload types: `crates/contracts/proto/contracts.proto`
  (package `contracts.v1`, a type schema only, no services). This file describes both in prose; if they disagree,
  the code wins and this file gets fixed.
- Background and the reasons behind each shape: PRD §6 on the `notes` branch (`git show origin/notes:PRD.md`).
- Changing a contract: add fields, never rename, renumber or delete them. Post `concept-change` in issue #11.

## Data types

All §6 types are generated by `crates/contracts/build.rs` (prost structs, `.proto` compiled with `protox`, so no `protoc`).
Use them as `contracts::Heartbeat`, `contracts::SplitPlan`, and so on. Every type has serde derives, so
`serde_json::to_string(&msg)` writes the JSON form below.

### JSON form (PRD §6.0)

- snake_case field names, exactly the `.proto` field names.
- Every top-level message has `schema_version` (currently `1`, constant `contracts::SCHEMA_VERSION`).
- Sizes are integer bytes; fields mirroring llama.cpp output keep MiB and say so (`free_mib`).
- Times are RFC 3339 UTC strings. Durations are integers with a unit suffix (`_ms`, `_s`).
- `null` means unknown or not measured. Missing fields read as their default; unknown fields are ignored.
- Enums are strings: lower-case for kinds and states the PRD writes in lower case (`"running"`, `"node_lost"`,
  `"llama_default"`, `"helper"`), upper-case for the §5.6 states (`"SERVING"`, `"ACTIVE"`), and the §6.11
  spelling for error codes (`"E_PORT_IN_USE"`). An unknown string reads as the enum's `Unspecified` value.
- These lists are `null` when empty: `StartRpcServerArgs.devices`, `SplitPlan.tensor_split`,
  `LaunchSpec.tensor_split`, `LaunchSpec.devices`, `DevicePlacement.actual_layers`, `LlamaServerStatus.metrics`,
  `LlamaServerStatus.slots`.
- Layer ranges (`layers`, `planned_layers`, `actual_layers`) are two-element arrays `[first, last]`, inclusive.

### Command and CommandResult (the one shape that differs from PRD §6.3)

`Command.kind` and `args` work as §6.3 shows. `CommandResult` adds a `kind` field that echoes the command kind,
so a reader knows which shape `data` has. It is absent when the command failed without data.

| `kind` | `args` (Rust type) | `data` on success (Rust type) |
|---|---|---|
| `start_rpc_server` | `StartRpcServerArgs` (every field optional; null = rpc-server default) | `StartRpcServerResult { pid, banner: RpcServerBanner }` |
| `stop_rpc_server` | `StopRpcServerArgs` (`{}`) | `StopRpcServerResult { exit_code }` |
| `probe` | `ProbeArgs` (`{}`) | `NodeCapabilities` |
| `speed_probe` | `SpeedProbeArgs { method }` (method is O-22) | `SpeedInfo` |
| `netcheck` | `NetcheckArgs { target_addr, duration_s }` | `NetcheckResult` |

In Rust: `Command.args: Option<command::Args>` and `CommandResult.data: Option<command_result::Data>`.

## Control plane: SpacetimeDB tables and reducers (D-13)

- **Module:** `crates/control` (crate `control`), on SpacetimeDB **2.14.1**. The `spacetimedb` crate, the
  `spacetimedb-sdk` crate and the `spacetime` CLI/server on main must all be exactly 2.14.1.
- **Server:** `spacetime start` on main listens on **0.0.0.0:3000** (HTTP and WebSocket), and clients connect to
  `http://<main-ip>:3000`.
- **Ports in use:**
  - 3000: SpacetimeDB on main.
  - 50052: rpc-server.
  - 8080: llama-server on main.
  - 50060: `netcheck serve` (O-17, decided 7:55pm).
  - Agents don't listen on any port.
- **Database name:** `pool` (Aayo, Sat 7:55pm; `contracts::defaults::DB_NAME`). Tests use `pool-smoke` so they never
  touch the real one.
- **Timings (O-26, Aayo 7:55pm):** heartbeat every 1000 ms; a node is LOST after 6000 ms without one; the coordinator
  waits up to 120 s for llama-server `/health`. Constants in `contracts::defaults`; TOML config may override.
- **Publish (main only):** `spacetime publish -s local -p crates/control pool -y`. The publisher's identity
  becomes admin. Always pass `-s local`: the CLI's default server is maincloud (hosted), which D-02 rules out.
- **Client bindings:** `contracts::control` (generated, committed). Other machines build without the CLI. After any
  change to `crates/control`, run this on a machine with the CLI and commit the result:
  `spacetime generate --lang rust --out-dir crates/contracts/src/control --module-path crates/control -y`.
- **Glue:** `contracts::control_glue::{node_info, heartbeat_info}` builds the reducer arguments from
  `contracts::NodeCapabilities` and `contracts::Heartbeat`.
- **Rule:** reducers only store and validate state. Module code can't reach the LAN, so starting llama.cpp, probing
  hardware and running netcheck stay in the agent and coordinator processes.
- **Column conventions:** enum-like columns hold the §6 JSON spellings as strings (`"running"`, `"ACTIVE"`,
  `"SERVING"`, `"node_lost"`, `"E_PORT_IN_USE"`). Full §6 payloads ride in `*_json` columns as the contracts serde JSON.

### Tables

All tables are public except `admin`.

| Table (Rust row type) | Key | What it holds | Written by |
|---|---|---|---|
| `node` (`NodeRow`) | `node_id`; `identity` unique | One row per machine: role, §5.6 `state` (REGISTERED, READY, ACTIVE, LOST), `online`, hostname, os_family, arch, cpu_model, logical_cores, total/available memory bytes, `devices` (name, backend, total_mib, free_mib, unified_memory), llama_build, llama_commit, rpc_protocol, rpc_server_devices, addresses, registered_at, last_seen, `caps_json` (§6.1) | register_node, update_capabilities, send_heartbeat, connect/disconnect, set_cluster_status |
| `heartbeat` (`HeartbeatRow`) | `node_id` | The latest heartbeat per node (overwritten): received_at, seq, rpc_state, rpc_pid, rpc_port, port_accepting, cpu_util_pct, mem_used_bytes, relay bytes in/out and graph computes, on_ac, battery_pct, last_error code/message, `heartbeat_json` (§6.2) | send_heartbeat |
| `command` (`CommandRow`) | `command_id` (auto); btree on `node_id` | §6.3 command and result: kind, `args_json` (the Command `args` object), `status` (pending, running, ok, failed), `result_json` (the CommandResult `data` object), error_code, error_message, created_at, claimed_at, finished_at | issue_command, claim_command, complete_command |
| `event` (`EventRow`) | `seq` (auto) | §6.10 history, append-only: at, kind, node_id, plan_id, message, data_json | the reducers themselves, and record_event |
| `split_plan` (`SplitPlanRow`) | `plan_id` | §6.5: model_id, strategy, fits, created_at, `plan_json` | set_split_plan |
| `cluster_status` (`ClusterStatusRow`) | `id` = 0 (one row) | §5.6 `cluster_state` (starts EMPTY), plan_id, model_id, endpoint, updated_at, `status_json` (§6.7) | init, set_cluster_status, disconnect (SERVING to DEGRADED) |
| `admin` (private) | `identity` | Identities allowed to call the coordinator reducers | init (publisher), add_admin |

### Reducers

| Reducer | Caller | Arguments | Effect and events |
|---|---|---|---|
| `register_node` | agent | `info: NodeInfo, caps_json` | Binds `node_id` to the caller's identity (one identity per node). New node: REGISTERED, logs `node_registered`. Node that was LOST: REGISTERED, logs `node_recovered`. Otherwise: keeps its state, logs `node_capabilities_changed`. Logs `version_mismatch` when llama.cpp builds or RPC protocols differ across non-LOST nodes. |
| `update_capabilities` | agent (owner) | `info: NodeInfo, caps_json` | Replaces the capability columns and keeps the state. Logs `node_capabilities_changed`. |
| `send_heartbeat` | agent (owner) | `hb: HeartbeatInfo, heartbeat_json` | Overwrites the heartbeat row and refreshes `last_seen`. Logs `rpc_server_started` or `rpc_server_exited` when the rpc-server state changes. REGISTERED becomes READY once rpc-server is running and accepting connections, or right away for `main`. A helper whose rpc-server stops goes from READY back to REGISTERED. Ignores old or duplicate `seq`. |
| `claim_command` | agent (owner) | `command_id` | Moves pending to running. Fails if the command isn't pending. |
| `complete_command` | agent (owner) | `command_id, ok, result_json, error_code: Option, error_message: Option` | Moves running to ok or failed. Idempotent. |
| `record_event` | coordinator, or a registered agent | `kind, node_id, plan_id, message, data_json` | Appends an event seen outside the module (placement_mismatch, request_failed, llama_server_exited, netcheck_result, bench_completed, ...). The kind must be in the §6.10 list. |
| `issue_command` | coordinator (admin) | `node_id, kind, args_json` | Inserts a pending command for an online node. The kind must be one of the 5 kinds in §6.3. |
| `set_split_plan` | coordinator (admin) | `plan_id, model_id, strategy, fits, plan_json` | Upserts the plan and logs `plan_created` or `plan_rejected`. Doesn't change the cluster state. |
| `set_cluster_status` | coordinator (admin) | `cluster_state, plan_id, model_id, endpoint, active_node_ids, status_json` | Allows only §5.6 transitions; any other fails with `E_INTERNAL: illegal cluster transition`. Entering SERVING moves the nodes in `active_node_ids` from READY to ACTIVE. Entering STOPPED or FAILED moves ACTIVE nodes back to READY. Logs `launch_started`, `llama_server_ready`, `recovery_started`, `recovery_succeeded` and `recovery_failed`. |
| `add_admin` | admin | `identity` | Authorizes another identity (the coordinator's own SDK identity), so no token gets copied around. |
| `init` (lifecycle) | server | none | Makes the publisher admin and creates `cluster_status` row 0 in state EMPTY. |
| `client_connected` (lifecycle) | server | none | Sets `online = true` for a known agent. |
| `client_disconnected` (lifecycle) | server | none | Marks a known agent offline and LOST, and logs `node_lost`. If that node was ACTIVE while the pool was SERVING, the pool goes to DEGRADED. |

Notes on the reducers:
- **Why `send_heartbeat`:** Aries' list called it `heartbeat`. The `heartbeat` table already generates an accessor
  named `heartbeat`, and Rust rejects a reducer with the same name.
- **Errors:** every error starts with a §6.11 code (`E_CONFIG: ...`) and rolls the whole call back. SDK callers see
  it in the generated `<reducer>_then` callback; CLI callers get HTTP 530.
- **CLI calls:** `spacetime call` and `spacetime sql` trigger `client_connected` and `client_disconnected` for the
  CLI's identity. If you register a node from the CLI, it shows as LOST right after the call.
- **Not in the module yet:** a heartbeat-timeout sweep for agents that hang while still connected (WP-9, O-26).

### Agent pattern (WP-3)

1. Connect with `contracts::control::DbConnection` and call `register_node`.
2. Subscribe to `SELECT * FROM command WHERE node_id = '<me>'`.
3. For each pending row: call `claim_command`, do the work on its own thread, then call `complete_command`.
4. Call `send_heartbeat` every `heartbeat_interval_ms`.

The ignored test `live_register_node_round_trip` in `crates/contracts/tests/control.rs` shows connect, call and
subscribe.

### Live status without code

`spacetime subscribe -s local <db> "SELECT * FROM node"` and `spacetime sql -s local <db> "SELECT * FROM event"`.
The CLI marks both commands UNSTABLE.
