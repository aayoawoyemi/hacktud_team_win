2. The problems

Aayo's brother · ~45 s

  • Compute is scarce. A model has to fit in GPU memory. A machine big enough costs thousands.
  • Data is private. Law and healthcare can't send records to a cloud AI. A server costs too much. So they go without.
  • Hardware sits idle. Offices already own capable computers. Each is too small alone; together they have enough memory.

3. Live demo: the database is the point

Preston · ~2 min · say it in your own words

01 pool: point at the three machines
  • One model, split across three laptops. Main (M3) holds the file; each M5 holds a block of layers.
Ask a question in the chat; talk while it streams
  • Each light on the wires is a token crossing laptops. Under 1 ms per hop.
  • Point at first-token time and tok/s. Don't linger: move to the database.
02 spacetimedb: spend the most time here
  • The whole pool lives in SpacetimeDB. Every machine is a row; every order is a row.
  • Agents register, send a heartbeat every second (point at seq ticking).
  • The coordinator writes the plan and commands; agents carry them out; state goes EMPTY → PLANNED → STARTING_HELPERS → LAUNCHING → SERVING.
  • Nobody typed commands on the helpers. The database rejects illegal state changes.
  • Ask a question here: the machines' rows light up as the answer passes through them.
  • Click a preset in "ask the database" (who holds which layers): live answer from the control plane.
  • Say, don't show: a new laptop can join while it keeps answering; if one drops, it re-plans and recovers.
Hand-off:
  • "Aayo has the numbers."

Likely questions

Anyone · one sentence each

  • Faster than one machine? It runs models none can hold. Sustained, the pool holds 11-12.5 tok/s; one Air throttles to 8-9.
  • Why wired? Every token crosses every machine; Ethernet is under 1 ms per hop. Venue Wi-Fi blocked laptop-to-laptop traffic. It works on any network, slower on Wi-Fi.
  • Why SpacetimeDB? Registry, heartbeats, commands, status and history are tables; no server to write, and illegal state changes are rejected.
  • Why Rust? One language from the database module (WebAssembly) to the agents; generated bindings make a mismatch a compile error.
  • Laptop dies? The coordinator re-plans on the rest and relaunches.
  • Is this EXO? Same idea of pooling devices; Oasis is an offline kit for hardware an office already owns, with SpacetimeDB holding the cluster state.
  • Those 04 numbers? Model makers' published benchmarks; machine counts are memory math, not runs.
